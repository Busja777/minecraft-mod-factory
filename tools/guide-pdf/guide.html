Studio, CurseForge-Helfer und Makros

Minecraft Mod Factory · Schritt-für-Schritt-Anleitung für den Betreiber · Stand 18.11.2026

Alles liegt in einem Ordner: ~/Desktop/minecraft-mod-factory. Starter und Anleitungen findest du darin unter Macros/. Diese Anleitung zeigt beide Wege, CurseForge-Formulare ausfüllen zu lassen: den Browser-Helfer (fertig, sofort nutzbar) und Keyboard-Maestro-Makros (baust du einmal selbst).

Drei Regeln, die immer gelten
  • Den letzten Klick machst du. Weder Helfer noch Makro klicken auf Create, Save, Apply, Upload oder Add File.
  • Login, Captcha und 2FA löst immer du. Nichts davon wird umgangen. Der Helfer wartet so lange.
  • Ein Projekt pro Lauf, in normalem Tempo. Kein Massenbetrieb.

Das Studio (dein Startpunkt)

Doppelklick auf Macros/Studio.command. Dein Browser öffnet das Dashboard (läuft nur auf deinem Mac).

AbschnittWas du tust
Jetzt fälligDer Termin ist da. „Jetzt veröffentlichen“ startet den Komplettlauf. Du klickst nur Create, Apply und Add File.
Wartet auf dein GoPacks nacheinander prüfen. Passt alles: Go. Passt ein Teil nicht: dort Ändern, kurz schreiben was, am Ende An Claude zurückgeben.
Wartet auf ClaudeNichts. Sag Claude in der nächsten Sitzung „bearbeite die Studio-Notizen“.
EingeplantNichts. Der Termin steht dran. „Go zurücknehmen“ geht jederzeit.
UpdatesNur zur Info. Updates bestehender Projekte brauchen kein Go.

Go ist gesperrt, solange Notizen offen sind oder eine automatische Prüfung rot ist. Der Grund steht direkt unter dem Knopf.

Teil 1: Der Browser-Helfer (Hauptweg)

Der Helfer füllt die CurseForge-Formulare aus, für die es keine Schnittstelle gibt: neues Projekt anlegen, Cover und Media, Skinpack-Datei hochladen. Am Ende hält er an.

Einmalig einrichten (ca. 15 Minuten)

  1. Doppelklick auf Macros/CurseForge.command. Meldet macOS beim ersten Mal „nicht verifizierter Entwickler“: Rechtsklick → Öffnen → Öffnen.
  2. Im Menü l tippen und ↩ drücken. Es öffnet sich ein eigenes Chrome-Fenster.
  3. Dort ganz normal bei CurseForge einloggen. Danach im Terminal ↩ drücken. Das Fenster merkt sich den Login. Dein normales Chrome bleibt unberührt.
  4. Probelauf: Starter erneut öffnen, „Cover & Media: Glowing Samurai“ wählen und zuschauen. Am Ende nicht auf Apply klicken, sondern das Fenster schließen.
  5. Steht in der Zusammenfassung „⚠ … nicht gefunden“: im Menü i wählen, genau diese Seite öffnen, ↩, dann q und Claude Bescheid geben.

Im Alltag

  1. Doppelklick auf Macros/CurseForge.command. Der Helfer holt die neuesten Daten und zeigt die offenen Aufgaben.
  2. Nummer eintippen und ↩. Chrome füllt alles aus. Nicht ins Fenster klicken, solange es arbeitet.
  3. Im Terminal steht, was erledigt ist und was du noch prüfen oder tun sollst.
  4. Prüfen, Rest erledigen und selbst abschicken. Danach das Fenster schließen.
Bei Skinpack-Updates
Der neue Beschreibungsabschnitt liegt schon in der Zwischenablage. Unter Description fügst du ihn vor „How to install“ mit ⌘V ein.
Bei neuen Projekten
Alles läuft in einem Durchgang: General → Description → License (du klickst Create), dann Media (du klickst Apply), dann File (du klickst Add File).

Befehle für das Terminal

BefehlWirkung

Teil 2: Makros mit Keyboard Maestro anlegen

Die Makros machen dasselbe wie der Helfer, aber per Hotkey in deinem normalen Chrome. Du baust sie einmal. Danach musst du sie nie anpassen, weil sie immer dieselben Dateien lesen.

So hängen Befehl und Makro zusammen

Vor jedem Makro-Lauf füllst du den Übergabe-Ordner Macros/aktuell/ mit einem Befehl. Das Makro liest die Werte von dort.

SituationBefehl im Terminal (im Projektordner)Makro
Neues Projekt, Modnpm run macro -- --mod <modId>⌃⌥N Neues Projekt
Neues Projekt, Skinpacknpm run macro -- --skinpack <slug>⌃⌥N Neues Projekt
Seite auffrischennpm run macro -- --skinpack <slug> --refresh⌃⌥M Cover & Media
Skinpack-Updatenpm run macro -- --skinpack <slug> --update⌃⌥U Skinpack-Update

Schritt 1: Keyboard Maestro einrichten (ca. 10 Minuten)

  1. Keyboard Maestro öffnen (Download auf keyboardmaestro.com, 30 Tage gratis, danach einmalig kostenpflichtig).
  2. Rechte geben unter Systemeinstellungen → Datenschutz & Sicherheit:
    • Bedienungshilfen: „Keyboard Maestro“ und „Keyboard Maestro Engine“ erlauben.
    • Bildschirmaufnahme: „Keyboard Maestro Engine“ erlauben. Das braucht die Bildsuche.
  3. Links unten + → neue Makro-Gruppe mit dem Namen CurseForge.
  4. Rechts bei der Gruppe: Available in these applications → Google Chrome. Die Hotkeys gelten dann nur in Chrome.
  5. In Chrome bei CurseForge eingeloggt bleiben. Das Makro loggt sich nie selbst ein. Chrome-Zoom auf 100 % lassen.

Aktionen fügst du über New Action (⌘K) hinzu und suchst sie per Namen.

Warum Bildsuche statt fester Koordinaten? Das Makro findet das Label, egal wo das Fenster liegt oder wie weit gescrollt ist.

Schritt 3: Hilfs-Makro „Datei wählen“ (das Herzstück)

Damit lädt jedes Makro Dateien hoch. Es bedient das Dateifenster von macOS.

  1. Neues Makro in der Gruppe CurseForge, Name: Datei wählen.
  2. Trigger: This macro is triggered by: Subroutine, Parameter: Local_Pfad.
  3. Aktionen in dieser Reihenfolge:
    1. Pause 1 s (das Dateifenster öffnet sich)
    2. Type a Keystroke ⌘⇧G („Gehe zu Ordner“)
    3. Pause 0,5 s
    4. Insert Text by Pasting %Variable%Local_Pfad%
    5. Pause 0,5 s, dann Type a Keystroke ↩ (springt zur Datei)
    6. Pause 0,5 s, dann Type a Keystroke ↩ (lädt hoch)

Aufruf aus anderen Makros: Aktion Execute a Subroutine → Datei wählen, Parameter z. B. %Variable%CF_LogoPfad%. Vorher muss das Makro auf den Upload-Knopf der Seite geklickt haben.

Schritt 4: Makro „CF: Neues Projekt“ ⌃⌥N

  1. Trigger: Hot Key ⌃⌥N.
  2. Werte laden (in einer Aktion Group, je ein Read a File):
    name.txt → CF_Name, summary.txt → CF_Summary, kategorie.txt → CF_Kategorie, zusatz-kategorien.txt → CF_Zusatz, lizenz.txt → CF_Lizenz, verbreitung.txt → CF_Verbreitung, quellcode.txt → CF_Quellcode, beschreibung.md → CF_Beschreibung, logo-pfad.txt → CF_LogoPfad.
  3. Open URL https://authors.curseforge.com, dann Pause Until (Found Image: Knopf „Start Project“).
  4. Klick auf „Start Project“, dann das Spiel, dann die Klasse (Mods bzw. Skins). Je ein Move or Click Mouse mit Bildsuche, dazwischen Pause 1 s.
  5. Pro Textfeld zwei Aktionen, Klick neben das Label und Einfügen: Project name → CF_Name, Summary → CF_Summary, Source Code → CF_Quellcode.
  6. Dropdowns (Main category, License, Distribution): hineinklicken, Wert einfügen, ↩. Zickt ein Dropdown, lass es weg und wähle es beim Prüfen selbst.
  7. Logo: Klick auf den Logo-Upload, dann Execute a Subroutine Datei wählen mit %Variable%CF_LogoPfad%.
  8. Beschreibung: ins Description-Feld klicken, %Variable%CF_Beschreibung% einfügen.
  9. Alert: „Alles ausgefüllt. Bitte prüfen und selbst auf Create klicken. Danach Cover über ⌃⌥M hochladen.“

Schritt 5: Makro „CF: Cover & Media“ ⌃⌥M

Starten, wenn die Projektseite offen ist (nach Create oder zum Auffrischen).

  1. Werte laden: cover-pfad.txt → CF_CoverPfad, media-titel.txt → CF_MediaTitel, media-beschreibung.txt → CF_MediaBeschreibung.
  2. Klick auf den Reiter Media, dann auf Upload / Add Image.
  3. Execute a Subroutine Datei wählen mit %Variable%CF_CoverPfad%.
  4. Title-Feld: %Variable%CF_MediaTitel%. Bei Skinpacks muss das genau MCPEDL sein, sonst übernimmt MCPEDL das Cover nicht.
  5. Description-Feld: %Variable%CF_MediaBeschreibung%, dann Klick auf den Stern Feature Media.
  6. Alert: „Prüfen und selbst speichern.“

Schritt 6: Makro „CF: Skinpack-Update“ ⌃⌥U

Starten, wenn die Projektseite des Skinpacks offen ist.

  1. Werte laden: datei-pfad.txt → CF_DateiPfad, changelog.md → CF_Changelog, beschreibungs-abschnitt.md → CF_Abschnitt.
  2. Reiter Files, dann Add File anklicken und Pause Until (Found Image: Upload-Bereich).
  3. Klick auf den Upload-Bereich, dann Execute a Subroutine Datei wählen mit %Variable%CF_DateiPfad%.
  4. Changelog-Feld: %Variable%CF_Changelog%. Release Type R anklicken.
  5. Game Versions: alle aktuellen 26.x anhaken. Ändert sich die Liste oft, mach das beim Prüfen selbst.
  6. Alert: „Datei bereit. Bitte prüfen und selbst hochladen.“
  7. Set Clipboard to Text %Variable%CF_Abschnitt%, dann Alert: „Der neue Beschreibungsabschnitt ist in der Zwischenablage. In Description vor ‚How to install‘ einfügen.“

Die .mcpack behält ihren Originalnamen. Daran erkennt das Projekt deinen Upload, also bitte nicht umbenennen.

Der Ordner wird bei jedem npm run macro komplett neu geschrieben. Die Textdateien enden ohne Zeilenumbruch, damit beim Einfügen nicht versehentlich Enter gedrückt wird.

Wenn ein Makro hakt

ProblemLösung
Makro klickt daneben oder findet ein Bild nichtFür diesen einen Schritt den Screenshot neu aufnehmen (⌃⇧⌘4). Der Rest bleibt.
Bildsuche findet nie etwasRecht „Bildschirmaufnahme“ für die Keyboard Maestro Engine prüfen. Chrome-Zoom auf 100 %.
Text wird nicht eingefügtPause davor auf 1 s erhöhen.
Dateifenster bleibt offenIn „Datei wählen“ die erste Pause auf 1,5 s erhöhen.
Makro läuft falsch weiterMenüleisten-Icon von Keyboard Maestro → Cancel All Macros.
Tipp zum Bauen: Bau jedes Makro, während das CurseForge-Formular daneben offen ist, und teste nach jedem zweiten Schritt mit dem Try-Knopf. Ein Projekt ausfüllen, ohne auf Create zu klicken, kostet nichts. Damit kannst du gefahrlos üben.

Stand 18.11.2026: Die Upload-Automatik ist noch nicht aktiv. Es fehlen drei Dinge:
  1. Der richtige Upload-Token (CurseForge → Account → My API Tokens, sieht aus wie xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx) in secrets.env unter CF_API_TOKEN. Der bisherige Wert dort gehört unter CF_CORE_API_KEY.
  2. Die neuen Abläufe müssen auf den Hauptzweig bei GitHub, weil nur dort Zeitpläne laufen.
  3. Ein erfolgreicher Test-Upload auf ein Bedrock-Projekt.
Bis dahin lädst du Update-Dateien mit dem Helfer oder dem Makro ⌃⌥U hoch.

Der Takt

  • Updates: abends zwischen 19 und 22 Uhr, höchstens eines pro Abend, pro Projekt alle 22 bis 25 Tage, nur mit echten neuen Inhalten.
  • Neue Projekte: nach deinem Go im Morgenfenster (6 bis 12 Uhr) an einem Upload-Tag, höchstens eines pro Tag.
  • Erinnerung zum Termin: einmal npm run studio -- zeitplan-installieren ausführen. Dein Mac prüft dann alle 30 Minuten die Termine und meldet sich. Entfernen: npm run studio -- zeitplan-entfernen.
